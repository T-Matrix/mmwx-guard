# 设计与安全参考取舍

本项目参考了妙妙屋、妙妙屋X、Beszel、Headscale 和 CrowdSec 的可公开实现与操作流程。参考的目标是复用成熟思路，不复制与本项目权限边界不相符的远程管理能力。

## 采用的设计

| 来源 | 采用内容 | 在本项目中的实现 |
| --- | --- | --- |
| 妙妙屋、妙妙屋X | 像素视觉、顶部主导航、右上角头像菜单、服务器详情内分区操作 | 保持中文像素风；服务器详情按概览、防护、服务识别、连接安全、事件拆分 |
| 妙妙屋X securechan | Ed25519 长期身份、X25519 临时密钥、HKDF、AES-GCM、序号防重放 | 独立实现于 `internal/protocol/secure.go`，绑定 Agent ID、Agent 身份标识和随机挑战 |
| Beszel | Hub 身份挑战、Agent 主动连接、列表快速识别异常状态 | 主控签名握手、Agent 固定指纹；Agent 无需开放管理端口 |
| Headscale | 一次性、过期、不可复用的注册授权，设备重新注册 | 注册令牌消费后失效；重新配对绑定原 Agent 身份标识，保留服务器策略和事件 |
| CrowdSec | 主控与执行端职责分离、事件审计、最小化执行端 API | Agent 只接受结构化策略、回滚、受校验更新和凭据轮换，不提供 Shell |

## 明确没有照搬

| 设计 | 不采用原因 |
| --- | --- |
| 妙妙屋旧式静态 Token 和 HTTP 回退 | 长期共享秘密难以独立撤销，HTTP 回退会降低已建立的 TLS/身份边界 |
| 通用 SSH 或任意命令执行入口 | 主控失陷时会直接变成所有服务器的 root 远程执行面 |
| `InsecureSkipVerify` 或允许关闭证书校验 | 会让首次注册与后续连接暴露给中间人；本项目仅允许 HTTPS，HTTP 只用于 localhost 测试 |
| 自动导入妙妙屋或 ForwardX 凭据 | 本项目只读取本机非敏感端口元数据用于展示，不扩大对其他系统的控制权 |
| 单个全局防护策略直接覆盖所有服务器 | 不同转发入口和业务端口风险不同，策略必须在服务器详情中显式配置和下发 |

## 操作流程原则

1. 概览只回答“哪里异常”，需要处理的 Agent 可一键筛选。
2. 所有改变某台机器的操作都进入该服务器详情，避免把公共配置误认为单机配置。
3. 连接状态拆分为在线、加密通道、主控已验证和凭据状态，避免只用一个绿色圆点掩盖降级连接。
4. 高风险操作使用确认框；异步操作显示进行中、成功或明确错误；一次性命令只在生成后展示。
5. 支持浏览器前进后退、键盘焦点循环、Escape 关闭和移动端布局，表格在窄屏允许受控横向滚动。

## 审计结论

- 主控与新 Agent 的应用层通信具备机密性、完整性、前向临时密钥和消息级防重放。
- 每个 Agent 使用独立凭据；轮换、撤销与重新配对都有事件记录，不共享全局 Agent Token。
- 主控没有远程 Shell，Agent systemd 只保留 `CAP_NET_ADMIN`，文件系统仅允许写 `/var/lib/mmwx-guard`。
- 主要剩余风险是主控本身作为信任根、首次注册依赖 HTTPS，以及 GitHub Release 哈希与制品同源。详细内容见根目录 `SECURITY.md`。
